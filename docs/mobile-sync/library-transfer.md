# 文库文件交换 · M3 首批

移动文库与笔记页的“导入与导出”入口支持 PaperQuay 文库 JSON 和 Markdown 文件。此功能是 M3 的首批实现；电脑取全文、直连/中继、私有云、外部文库映射、完整富文本和远程解析仍按原计划推进。

## 使用与范围

选择文件后先预览，默认选中新内容、跳过重复项。勾选重复项会使用新 ID 另存副本。关联笔记会明确显示连接到本次文献还是现有文献；缺少文献、存在多个匹配或未选中必要文献时，必须处理提示或取消该笔记后才能导入。

导入只创建记录，不覆盖、恢复或合并已有记录。当前账号和设备绑定、预览结果与内容关联在提交事务中重新检查；发生变化会保留预览并要求重看。整个批次与待同步队列一次保存，本地事务失败不会出现部分导入。保存完成后按既有同步协议继续发送，不能把本地保存当作服务端已确认。

单次最多 4 MiB（UTF-8 字节）、500 篇文献、500 条笔记。题录与笔记字段沿用同步协议的长度和结构限制。Markdown 文件保留正文，文件名作为笔记标题，创建独立笔记；不推测 front matter 中的文献 ID。

文库 JSON 导出当前设备已保存、未删除的题录与 Markdown 笔记。包括尚未同步的本机改动；存在冲突时明确提示导出当前可见内容。未保存草稿、PDF、批注、阅读位置、AI 会话和账号/设备/凭据配置不在此格式内。单篇 Markdown 导出保留正文；标题用于文件名。

导出使用文件内 `p1` / `n1` 引用，不携带原账号、设备、实体或操作 ID。关联文献缺失时仍保留待核对的文件内引用；不会静默将笔记改成独立笔记。导出的文本内容属于用户提供的题录与正文，内容本身可能包含用户主动记录的个人信息。

## 格式 v1

```json
{
  "format": "paperquay-library",
  "version": 1,
  "papers": [
    {
      "ref": "p1",
      "data": {
        "title": "研究示例",
        "authors": ["示例作者"],
        "year": "2026",
        "doi": null,
        "publication": null,
        "keywords": [],
        "abstractText": null
      }
    }
  ],
  "notes": [
    {
      "ref": "n1",
      "paperRef": "p1",
      "title": "阅读记录",
      "body": "# 阅读记录\n\n待核对的研究想法。",
      "format": "markdown"
    }
  ]
}
```

题录允许同步协议定义的 `organization` 分类字段；只有服务声明支持，或离线时已有可用的能力记录，才允许导入分类。已明确返回不支持的旧服务不能通过断网绕过检查。未知字段、版本、重复引用、非法 ID 或超出长度的内容明确拒绝。

去重优先使用规范化 DOI；没有可用 DOI 时比较完整题录。仅标题相同不会自动归并。笔记比较关联文献、标题和完整 Markdown；重复项仍需用户主动勾选才会新增副本。

## 平台行为

Web 通过浏览器下载 JSON/Markdown。原生容器使用 Capacitor Share 与 Filesystem Cache，只有用户点击导出才打开系统选择器；不会自动选择接收应用。文件准备完成后再次核对账号，过期准备会清除临时文件且不打开分享。

分享面板返回不能证明接收应用已经读取文件，所以已交给分享面板的文件留在系统管理的缓存中，避免过早删除造成空文件。系统可能随后清理缓存；下载或分享出去的文件不再跟随账号同步或清理操作撤回。原生分享的桥接测试和工程插件同步不替代真实设备的保存、取消与接收应用验证。

## 验证记录

自动化、浏览器下载与真实本机同步服务的证据见本轮 M3 检查点。此格式不是桌面现有完整备份或 Zotero/BibTeX/RIS 格式；这些适配器需要显式映射与各自的无损验证。
