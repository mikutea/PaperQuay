# M1 界面规格

概念通过内置 Image Gen 生成；这里只作为实现参考，界面由原生 HTML/CSS/React 控件呈现。示例题录/笔记属于测试内容，实际产品不得默认填入或冒充用户同步数据。

- `phone-library.png`：390 × 844 CSS 视口比例，手机文库、同步状态、搜索与三项底部导航。
- `tablet-notes.png`：1194 × 834 CSS 视口比例，210px 导航轨、300px 笔记列表、弹性编辑区。
- M1 只展示文库、笔记、账号。阅读/PDF/AI 在后续实现后加入，不以禁用或无效按钮代替功能。

## 颜色、字体与组件

沿用桌面 token：背景 `#fafaf9`，内容 `#ffffff`，文字 `#1c1917`，次要文字 `#57534e`，分隔 `#e7e5e4`，强调 `#0d9488`。成功/警告/错误通过图标、文字及颜色共同表达。系统中文无衬线字体；正文16px、次要14px、主标题24px、主要触控目标至少44px。列表以分隔线组织，不做卡片网格；圆角8–12px仅用于输入框/按钮/选择状态。

使用 lucide 风格轮廓图标，20–24px、1.75–2px 描边；导航选中状态为 teal。手机底部导航有安全区；平板左导航保持可见，主栏可横向展开。笔记编辑为真实 textarea/输入控件，正文与保存状态分开；请求未返回不代表本地未保存。

## 可见文案与必要状态

主导航：`文库`、`笔记`、`账号`；品牌：`PaperQuay`。搜索：`搜索文献`、`搜索笔记`；动作：`同步`、`新建笔记`、`登录`、`退出登录`、`查看冲突`、`保留当前版本`、`使用我的版本`。状态：`已同步`、`已保存在此设备`、`待同步`、`同步中`、`需要处理冲突`、`请重新登录`、`保存失败`。

登录/配置页使用相同排版和输入组件；未配置、空文库、没有笔记、加载失败均有真实原因和下一步动作。冲突页并排显示当前/尝试正文，手机纵向堆叠；明确动作提交前保留两个版本。账号页列设备会话，撤销与本机数据清理分开。

## 实现前记录的必要调整

1. 手机概念中的 `未归类` 筛选依赖后续分类模型，M1 删除该筛选行，保留真实搜索。此处不提供恒等筛选假交互。
2. 手动创建/编辑文献和笔记关联选择是端到端验证所需；在文库标题区增加 `添加文献`，详情区加入真实字段表单。移动端窄屏用详情页，平板用相邻面板。
3. 生成图中的样例摘要/笔记文案不进入默认数据；仅在测试账号中使用合成样例验证同版布局。
4. 图中的“已同步/已保存”由真实持久化与服务器状态驱动，不能硬编码。
5. 平板图中的 Markdown 标记保留在输入框中，避免将只读渲染图误当完整富文本编辑器。M1 不宣称富文本格式迁移完成。

## 验证记录要求

在同一次 QA 中用 view_image 查看两张概念图与最新浏览器截图；检查 copy、列表/面板布局、字体、palette、icon、间距和手机溢出。分别执行真实登录、同步、新建/编辑笔记、断网恢复、冲突处理、退出/撤销；记录故障及修复。浏览器通过不替代四类原生实机验收。
