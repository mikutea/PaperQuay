# 私有云 PDF · M3 首批

云副本保存用户主动选择的完整 PDF，供同一账号的其他设备下载。服务器默认关闭此能力；文库同步、打开本机 PDF 或公开链接都不会自动上传文件。本文说明私有副本链路；用户触发的缓存、云和公开链接顺序读取见 [按版本打开全文](pdf-sources.md)。在线电脑取文件和中继仍待开发。

## 使用入口

1. 在阅读器打开 PDF，先完成附件版本的元数据同步。
2. 手机从「更多阅读选项 → 私有云 PDF」进入；文件与版本面板也有「查看此版本的云副本」。确认文件名、大小与版本后，点击「上传此 PDF 到私有云」。
3. 另一台设备同步文库后，可在文件面板点击「从可用来源打开」，或在相同版本的云副本面板点击「下载云副本并阅读」。客户端核验完整大小和 SHA-256，再交给 PDF 阅读器解析并保存本机缓存。
4. 账号页的「私有云 PDF」集中显示额度和副本。文献或版本已删除的副本也留在列表中，可明确删除并释放云额度。

| 操作 | 云端 PDF | 文库、笔记、批注 | 本机 PDF 缓存 |
| --- | --- | --- | --- |
| 同步文库或打开文件 | 不自动上传 | 按原有协议同步 | 按阅读操作使用 |
| 显式上传 | 保存当前版本；相同内容重试不重复占用额度 | 不改正文、版本 revision 或变更日志 | 保留 |
| 下载并阅读 | 保留 | 阅读位置按既有规则保存 | 校验成功后写入 |
| 删除云副本 | 删除，释放云额度 | 保留 | 保留 |
| 删除文献或附件版本 | 保留，但不可再下载 | 按用户删除操作处理 | 遵循独立缓存策略 |
| 清除本机数据 | 保留 | 仅按本机清理范围处理 | 按本机清理范围删除 |

上传、删除的网络连接取消或超时，可能发生在服务器已经提交之后。界面会明确提示刷新状态确认，不会自动重试或假定已回滚。账号、登录会话、当前阅读任务或附件身份发生变化后，旧操作不能覆盖新界面或继续打开 PDF。

## 服务开关与边界

- `PAPERQUAY_CLOUD_PDF_ENABLED=1` 显式启用，默认 `0`。
- `PAPERQUAY_CLOUD_PDF_ACCOUNT_BYTES` 默认 1 GiB，可配置 1 byte–10 GiB；固定最多 64 MiB/文件、512 份/账号。该额度仅计算完整 PDF 原始字节，与文库 JSON 保留预算分别计算。
- 能力协商同时要求 `pdfStorage:true`、`features.privatePdfStorage:1` 和有效的 `cloudPdf` 限制对象。旧服务或关闭的服务不开放操作。
- 本进程同时最多 2 个传输、同一账号最多 1 个；收取上传正文前取得槽位，下载按 64 KiB 分块响应，完成写出或断连后释放。数据库动作尚未结束时仍保留槽位。每次传输有 45 秒绝对截止时间。
- 当前为单服务进程内的传输限制；多实例、反向代理带宽、账号总量和实际磁盘容量仍需要部署时验证。`finish` 只表示服务器完成写出，不能代替客户端哈希验证。

每个请求经过 OIDC 签名和登录会话校验；上传准入后还会在提交事务内重新检查撤销、文献、版本、哈希和配额。关闭服务时返回明确的未开放错误。没有公开分享链接或任意来源 URL 抓取接口。

文件保存在自托管服务的 PostgreSQL bytea 中，服务器可访问这些字节；本批未实现端到端加密。上传前与下载后均执行客户端完整文件检查，服务端检查头尾标记、长度和 SHA-256；服务器的检查不等同于完整 PDF 语义或安全解析。

## 持久化与删除竞态

迁移 004 新增云表、独立计账字段和附件内部 generation。复合账号外键、FORCE RLS、数据库哈希/长度约束和账号锁内的额度触发器共同约束写入。内容、计数和删除状态在同一个 PostgreSQL 事务提交；本批没有文件系统与数据库双写。

删除副本会推进 generation，即使当前副本尚不存在。删除之前准入、之后才提交的上传返回 `CLOUD_PDF_CHANGED`，不会把刚删除的副本重新保存。之后用户主动发起的新上传仍允许保存。此内部字段不进入同步 DTO，也不改变记录 revision 或 changelog。

逻辑配额不包含 TOAST、索引、WAL、膨胀或备份，因此不能当作实际磁盘用量。下载仍会从数据库读取完整 Buffer；分块发送控制 socket 背压，不消除完整文件的内存驻留。正式服务需根据进程数量、数据库内存和实际流量设置容量。
