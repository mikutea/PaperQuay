# PaperQuay 手机、平板与账号同步

本方案面向可长期使用、可维护、可恢复的产品质量。完整目标是让 iPhone、Android 手机、iPad 和 Android 平板拥有与桌面端相同的业务能力，并按触控、屏幕和系统限制重新组织界面。阅读、笔记、划线和独立调用大模型 API 是核心能力。

**当前阶段：M0 已完成，M1 账号与同步基础已实现并完成本机集成验收；CI 与代码/安全审查由 [PR #34](https://github.com/mikutea/PaperQuay/pull/34) 跟踪。** 53 项完整需求与 27 组验收场景仍按 M0–M5 推进；本次并不代表原生端或完整业务已经交付。代码、自动化验证、真实设备验证和生产验收分别记录。

## 已确定的产品决策

- 服务器默认保存账号、文库元数据、个人记录和必要的文本衍生数据，不自动保存整个 PDF 文库。
- 阅读时按版本寻找可用全文：已验证的临时缓存、公开全文源、同账号在线电脑、用户主动上传的私有云副本。来源选择考虑可用性、超时、流量和版本；不会串行无限等待电脑。
- 手机和平板默认不保留整库 PDF。临时文件和内存缓存不可完全避免，但可查看和清理；离线保存须用户主动选择。
- 电脑开着不等于一定可连接。直传失败可以在政策允许时临时中继；中继占用服务器带宽，默认不留存 PDF。
- 移动 AI 可使用用户在该设备配置的外部模型 API，电脑离线不影响这条路线。API 密钥不进入普通账号同步。
- 同步以记录和版本为单位；不同版本的 PDF 不自动继承页码、划线和坐标。并发正文保留双方，删除与恢复明确分开。
- 既有 WebDAV 备份、可信局域网共享和本地库继续独立工作。新功能不自动接管旧库或上传旧数据。

## 已知基线与边界

基线为 `main` 的 `6e137a3d81e3f1198766c9d199c9c68440dff7f3`。现有桌面端存在 SQLite 文库、localStorage 阅读历史、独立笔记与 radar 状态；这些内容不能原样打包成同步协议。

旧阅读坐标没有历史文件 hash 证据时只能保留为未验证记录；不能用当前文件 hash 猜测旧坐标属于哪个版本。富文本笔记的真值是 `contentJson`，M1 不将其压平为 Markdown 后回写。

现有发布说明中的启动 SQLite 路径交换 P2 仍独立存在；账号服务器和同步测试不会自动修复或抵消此问题。面向正式发布时必须按其实际影响范围关闭该门槛。

本轮开发在隔离工作树和合成数据上进行。CN-DC-01 目前是部署候选；生产部署、域名、证书、容量和真实设备验收在结果可审阅后单独执行。未验证的原生包、外网链路、性能和恢复能力均不得标为通过。
