## 已复现并修复的问题

- **取消变成再次提交：** 取消按钮在同一点击中被 React 复用成 submit 按钮。取消处理阻止默认动作，并区分按钮 key。生产预览用真实 HTTP 计数验证：首个分块后取消，等待超过完整响应时长，仍只有一次请求、一次分块，连接已关闭且输出不再追加；手动再次发送才增加一次请求。
- **离线重开被误报文件无效：** 缓存 Blob 的字节数和 SHA-256 与版本一致，实际失败的是断网后的 `pdf.worker.min.mjs` 请求。现把匹配的 worker、CMap、标准字体、WASM 有限资源随阅读器按需模块打包，区分阅读器资源错误与文件错误。已验证缓存重开三次及断网后首次中文页渲染，没有额外 HTTP 资源请求。
- **首次导入被缓存恢复打断：** 新附件版本发布后，自动恢复曾抢占正在导入的任务。初次打开协调器防止并发抢占；实际新文献首次导入已成功。
- **返回误报未保存：** 本地提交完成早于 React 状态更新时，父级守卫曾读到旧状态。阅读位置、评论与并行批注共享即时 dirty 汇总；返回前发布实时状态。新草稿、失败写入、其他未完成写入继续受保护。生命周期标记在卸载提交时失效，旧返回续体不能影响新账号阅读器。

另对取消/超时清理按已安装 PDF.js 契约做交叉复核并修复：底层 Worker 未 ready 时也由应用明确释放；文本流取消传 Error，等待取消确认最多 2 秒。12 项直接使用实际 PDFWorker/MessageHandler 的回归通过；最终浏览器记录真实 Worker 创建 4 个、离开阅读器后终止 4 个。移动端最终 233 项测试全部通过。此机制分析不作为历史浏览器异常的已证实根因。
