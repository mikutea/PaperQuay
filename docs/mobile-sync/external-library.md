# 外部文库快照映射 · M3

在“导入与导出 → 外部文库”中选择 JSON 快照，比较来源与本机题录，确认后保存。首次接入建立来源条目到 PaperQuay 文献的关联；以后选择同一来源的新快照，继续更新原文献。

此入口当前读取用户选择的文件。没有后台轮询 Zotero，也不会登录外部账号、下载附件或写回外部文库。来源映射与上次来源题录保存在本设备的当前账号下；题录继续通过现有同步协议跨端同步。另一设备需要重新选择来源并明确关联已有文献。四类实机继续暂缓。

## 支持的文件

1. **Zotero Web API v3 JSON 条目数组**：每条包含 `key`、`version`、`library` 与 `data`。这是 API 快照，不等同于 Zotero 的普通 CSL JSON、RDF 或 BibTeX 导出。适配依据是 [Zotero 官方 API 文档](https://www.zotero.org/support/dev/web_api/v3/basics)与[类型和字段说明](https://www.zotero.org/support/dev/web_api/v3/types_and_fields)。
2. **PaperQuay 外部文库快照 v1**：由受信任的外部库适配器提供明确、稳定的来源库键、条目键和递增条目版本。格式如下。

```json
{
  "format": "paperquay-external-library",
  "version": 1,
  "source": { "kind": "external", "key": "research-library", "name": "研究文库" },
  "items": [
    {
      "key": "paper-001",
      "version": 1,
      "data": {
        "title": "研究示例",
        "doi": null,
        "year": "2026",
        "publication": null,
        "abstractText": null,
        "authors": ["示例作者"],
        "keywords": []
      }
    }
  ]
}
```

每次最多 4 MiB UTF-8 文本、500 条来源记录；拒绝无效 UTF-8、重复条目键、跨来源混合、未知中立格式字段和不符合协议的题录。JSON 深度最多 16 层。来源库键与普通外部条目键限 1–128 个字母、数字、点、下划线或连字符，首字符为字母或数字，不能用路径或 URL。条目版本为非负安全整数。

Zotero 的库键取正整数库 ID，来源种类区分个人库与群组库；条目键为八位大写字母或数字。响应信封与 `data` 中同时出现的 key/version 必须一致。仅一个来源的已删除、附件、笔记或子条目列表可产生空预览，不会产生任何删除操作。

## 题录和字段变化

本次只维护标题、DOI、年份、出版来源、摘要、作者和关键词七个字段。当前 `organization` 收藏、阅读状态、标签、集合和队列始终保留本地值，外部文件不能覆盖它们。

Zotero 适配器只取 author 角色，作者保存为显示名称；其他角色、姓名结构和机构标记的变化会提示。日期只取能唯一确定的四位年份。Zotero 标签不自动转成关键词；附件、子条目、笔记、文献类型、卷期页、链接及其他未支持信息明确提示跳过。文字中的 HTML 标记仅作为普通文字显示，不执行或读取图片。

普通 BibTeX / RIS / PaperQuay JSON 仍走原“导入”入口，它们的重复副本语义没有改变。外部映射、来源键、版本基线不会混入题录同步载荷或普通文库 JSON 导出；这两类导出不是本机来源映射的备份。

## 再次导入的规则

来源身份由“来源种类 + 库键 + 条目键”确定，文件名和来源显示名称不参与身份。映射建立后使用稳定的 PaperQuay UUID；不将来源路径当作云端实体 ID。

| 当前情况 | 预览与保存行为 |
| --- | --- |
| 首次接入且没有重复题录 | 新建文献和来源映射 |
| 相同 DOI 或完整题录已有候选 | 必须选择具体文献关联、另存副本或跳过；不按标题自动合并 |
| 首次关联但题录存在差异 | 展示差异，明确采用来源或保留本地冲突字段后才允许保存 |
| 仅来源修改某字段 | 更新该字段 |
| 仅本地修改某字段 | 保留该字段 |
| 双方修改同字段为不同内容 | 阻止保存，明确选择后处理冲突字段，其他字段仍按预览合并 |
| 来源版本相同且内容相同 | 保持原文献 ID，不重复排队 |
| 来源版本降低 | 跳过旧版本，不回退基线 |
| 来源版本相同但内容不同 | 阻止该条，要求取得有效来源版本 |
| 目标有待发送、发送中、结果未知、拒绝或冲突 | 阻止更新，先完成同步或处理冲突 |
| 目标删除或不可见 | 不恢复、不偷偷创建替代文献 |
| 快照未包含某个原有条目 | 保留原文献和映射，不推断删除 |

一篇文献在此设备只能由一个来源条目维护，同批两个条目不能争用同一目标；需要多个独立来源副本时明确另存新文献。冲突选择“保留本地”仍推进已确认的来源基线，避免相同快照反复提示同一个冲突。

预览固定在用户实际比较过的工作区。收到新版本或本地状态变化时，预览明确过期、保存禁用；“重新比较当前文库”清除旧关联与冲突选择。提交还会在本机事务内重新计算整个计划，并核对账号、设备、generation、来源、选择、目标内容及状态。

## 持久化与恢复边界

来源映射、基线、混合新增/更新题录和 outbox 一次提交。批次中的容量错误、非法生成 ID 或本机事务失败均不留半批；保存完成后才显示成功并开始同步。更新使用真实服务端 revision，不能覆盖任何未完成操作，也不通过导入执行 restore/delete。

每账号每设备最多 50 个来源、10,000 条映射、32 MiB 映射 JSON，另受现有文库和 outbox 容量限制。同步失败不抹去已保存的来源基线或待发送操作；相应目标会保持待处理状态，后续来源版本不能绕过它。

Web 使用账号隔离的 IndexedDB，原生适配器使用同一工作区中的 SQLite 事务。本轮以真实 SQLite 文件验证重开和失败回滚，不能据此声称原生 WebView 或系统生命周期已验收。

清除本机账号数据会同时清除这些来源映射，界面已明确告知。服务端题录仍可重新拉取；下一次来源接入需重新确认关联。旧工作区无需破坏性迁移，缺少可选映射字段时正常读取。

实际 Zotero 账号/API 连通、自动增量读取、跨设备映射同步、来源映射单独备份与解除关联、外部附件/富文本笔记的无损接入仍属于后续工作，不计为本轮完成。
