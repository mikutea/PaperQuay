## Zotero 手动刷新

真实 Zotero 接口的条件读取可能返回 304，同时省略 `Zotero-API-Version` 和 `Last-Modified-Version`。客户端现在对这种情况执行一次相同条目 URL 的非条件读取，以普通 200 响应确认来源版本：

- 版本与请求游标相同且结果为空时，返回“没有新的变化”，不推进游标、不产生采用操作。
- 版本变新时，继续原有完整分页和删除通知流程。
- 版本回退、明确但非法的版本头、非条件请求或后续分页中的意外 304 仍拒绝。请求、字节数、退避和截止时间限制保持适用。

空标题、无效 DOI 或作者等题录错误仍使整轮失败，不静默跳过或部分采用。界面改为提示在 Zotero 中修正来源数据；本轮未采用，本机已采用的来源版本游标、现有文献和映射不因此改变。

这属于用户明确发起的 API 刷新，与 [文件快照映射](external-library.md) 分别记录；没有增加后台轮询或外部文库写回。

## 原生状态栏主题

Android 实机在应用运行期间从浅色切换到深色时，正文已切换，但状态栏仍保留浅色启动时的深色文字。当前 Capacitor 版本会将默认系统栏样式解析为启动时的具体样式，并在配置变化时重复应用这个结果。

原生入口现在监听与页面 CSS 相同的系统深浅色偏好，启动及主题变化时明确应用对应系统栏样式。Android 手机和平板、iOS 与 iPadOS 使用同一入口；Web 和 Windows／macOS 桌面页面不调用原生系统栏。四项回归覆盖双向切换、深色启动、监听清理、浏览器隔离及调用失败时继续启动；移动端全量 1,565 项、类型检查和构建通过。Apple 原生运行效果仍待签名与实机条件，不能以共享代码或测试替代。

## 文稿配色与标题

阅读器标题去掉白色发光阴影，使用主题文字和有底色的标题栏。PDF 文稿配色由桌面与 Web／原生移动端共用：默认跟随主题，在深色模式下降低纸张亮度并使用浅色文字；“柔和原图”只降低亮度、不反色；“原始颜色”用于核对彩图。配色选择保存在当前客户端，切换只影响阅读显示，不重新打开文档或改变批注坐标。

固定版面的夜间配色会改变页面颜色，不能当作原始色彩证据；核色时切回原始颜色。设计参考 [KOReader 的夜间与固定版面阅读选项](https://koreader.rocks/user_guide/) 和 [Mihon 的阅读背景设置](https://mihon.app/docs/guides/reader-settings)，将文字文稿与原图阅读区分处理。

隔离 Electron 已实际切换三种配色，重新加载后保留选择，深浅主题均可正常阅读。深色阅读区同时清除遗留的浅色渐变背景，并统一 PDF 页框颜色，避免深色文稿外仍留有白圈。结构化阅读的计数标记也使用对应主题颜色。本机根测试 1,633 项与移动端 1,565 项通过；根测试仅排除前文记录的本机策略拦截探针，全套 CI 不排除。
