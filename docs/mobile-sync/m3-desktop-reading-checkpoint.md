# 当前 PDF 的阅读位置与明确接续

2026-11-04。本轮已在旧桌面 Reader 接入实际 PDF 位置捕获、本次会话的本机记录、明确账号发布及按设备接续。入口为原生文库 PDF 的「工具 → 跨设备阅读位置」。检查不发送，登录、重连和重开不自动启用记录或跳页。

## 位置属于哪份内容

明确检查时，PDFJS `getData()`读取当前加载文档的完整字节，计算 SHA-256、长度和页数。主进程通过当前文库绑定重新读取实际导入附件，再核对账号中的文献与附件版本。证明上限为64 MiB。标题、文件名、路径、历史sourceKey或旧页码都不能代替版本证明。

存在多个合法版本时需明确选择。主进程在每次异步核验后检查账号、文库、当前绑定和源版本；文档访问器一旦退役，不会在返回原标签页后重新有效。

## 本机记录、发送与接续

| 用户动作 | 保存或应用的内容 | 后续行为 |
| --- | --- | --- |
| 开启「记录本次阅读位置」 | 当前已验证版本、实际最近点、最远点和会话先保存为账号/文库私有draft。 | 位置事件节流保存；回看改变最近点，最远点不回退。每点不联网、不重复读取完整PDF。 |
| 关闭位置面板 | 本次已明确开启的记录继续接收实际滚动事件。 | 明确停止、账号/设备/库/文档或能力变化会结束该会话；重启不会自动启用。 |
| 重新检查后确认发布 | 先固定并保存source、capture、原opId、entityId、sessionId、sequence与outbox，再发送原请求。 | 后续滚动另存draft，不能替换未知操作载荷。保存未确认只重试保存；旧设备原操作不能换身份重提。 |
| 选择一个设备位置并确认接续 | 主进程重新核对源和该记录revision，Reader重新验证当前加载文档，再精确应用该最近点。 | 默认不选；变更/删除的远端点作废。窗口无法精确表达的坐标明确拒绝，保持此前位置。 |

账号墓碑的恢复需单独确认，本机记录不会恢复账号内容。未知首次墓碑不猜文献版本。文件、题录、笔记与旧paperHistory不因该模块迁移或重写；普通Reader自身原有保存仍按用户阅读行为执行。

停止后的显示也保留账号归属。切到另一账号会清除旧最近点、最远点与时间；晚到的旧保存、停止或接续结果不能覆盖新账号状态。完整私有状态可经原生保存对话框备份，打开面板不会自动导出。
