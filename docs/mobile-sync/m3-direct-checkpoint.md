后续更新：外部文库快照映射已接通，最新进展见 [M3 外部库检查点](m3-external-checkpoint.md)。以下保留设备直连阶段的验证与边界。

已接通同账号在线电脑的设备直连，以及失败后的同请求临时中继回退。真实 Electron 与独立 Chrome 客户端已经完成传输、回退、旧客户端和取消验证。手机/平板实机按用户要求继续暂缓；M3 尚未整体完成。

10 月 28 日已补完超过 1 MiB 的分块传输、窄屏/大字号和关闭最后一个主窗口的验证。大文件测试发现并修复了重复遍历整个文库导致短期许可续期被阻塞的问题；每个分块仍重读并校验当前目标，完整工作区仍在存储和同步边界校验，没有放宽权限或期限。

## 实现

- 在原 `http-relay-v1` 能力上协商可选 `webrtc-data-v1`。同账号的不同已注册会话通过短期信令建立 DataChannel；直连最多六秒，电脑来源仍共享十五秒总上限。
- 失败后关闭 peer、丢弃不完整内容，再用原请求、并发槽和流量预算进入临时中继。不会重新创建请求、续租或重复扣预留流量；旧服务、旧提供方和没有 WebRTC 的客户端保留原中继路径。
- 双方每秒复核最多两秒的许可；提供方发送最后一块之前再次验证权限。消费者核对完整长度、SHA-256、PDF 外形并获得服务端完成回执后才返回字节，阅读器继续解析和核验当前版本，再写缓存。
- 控制查询、完成和回退请求按同一会话串行，避免与服务端角色占用检查冲突。已确认完成后 ACK 丢失或 peer 关闭不再触发错误回退；认证、撤销、墓碑、账号/目标变化和明确取消均终止读取。
- 桌面使用独立内存 session 的 sandbox renderer，只加载固定本地页面。账号令牌、文件路径、附件映射和授权句柄保留在主进程；私有 IPC 校验来源、主 frame、任务 nonce 与状态，每次只复制一个有界数据块。
- 主窗口生命周期与隐藏传输窗口分开计数；关闭最后一个实际窗口会停止提供并销毁传输窗口。界面区分直连、回退中和临时中继。

协议、线格式、回执与许可边界见 [设备直连约定](direct-transfer-contract.md)；配置和用户操作见 [在线电脑取文件](desktop-pdf.md)。没有新增数据库迁移或 WebRTC 原生依赖。

基础联调的实际选中候选为 `host ↔ host / UDP`。DataChannel 收到全部 9978 bytes，文件摘要和两页解析/缓存一致，直连过程没有 HTTP PDF content 请求。故障注入只让该测试客户端使用没有可用候选的 ICE 配置；同一个请求随后通过真实 HTTP 中继取得完整文件，一次点击至校验后取证约 7.2 秒。这是本机隔离环境的单次观测，不代表公网性能。

不支持 WebRTC 的独立客户端没有发起 direct 信令；取消正在进行的直连后，peer 关闭、没有中继内容请求、没有缓存写入。关闭桌面提供后，已校验本机缓存仍可离线重开。

扩展文件为 1,058,554 bytes、两页合成 PDF，实际 DataChannel 收到 65 个二进制分块，最终选中 `host ↔ host / UDP`，长度、SHA-256、PDF.js 解析和账号隔离缓存一致，直连没有 HTTP PDF content 请求。无法建立 ICE 连接时，同一租约通过真实 HTTP 中继取得相同文件，一次点击至校验后取证约 6.9 秒。该时间仅为本机隔离环境观测。

320、390、820、1280 像素和 200% 根字号已检查交互、截图及横向溢出。最后窗口验证在真实主窗口与隐藏 peer 同时存在时关闭主窗口，Electron 以 0 退出；客户端 peer 关闭、收取字节为 0、没有成功 content 请求和缓存写入。关闭后服务返回的 404 属于已终止请求，不是已完成文件传输。

测试只使用随机合成账号/元数据、独立浏览器 context 和独立 Electron profile。原生选文件入口只返回本次合成 PDF；系统浏览器启动入口导向受控 Chrome。后续授权跳转、回环回调、主进程文件读取、信令、WebRTC、HTTP、PDF.js 和 IndexedDB 都实际执行。测试未连接用户文库或生产服务。

## 复测与失败记录

首次根项目回归中的四项启动测试因夹具未接入新增生命周期模块而失败，已补入真实模块并复测通过。同批两个 Vite 模块加载超时、服务端一个旧云文件用例超时取消；定向复测及最终完整回归全部通过，没有放宽这些测试的超时或断言。

构建入口先遇到 npm 子进程找不到 npm，随后原生构建发现继承的 Python home 与解释器版本混用。改为直接执行仓库构建脚本，并仅在构建进程清理 Python home 变量后通过；没有修改系统环境或产品依赖。原失败日志保留。Vite 大包、原生编译器与开发运行时的既有提示单独记录，不作为签名安装验收。

扩展联调最初两次在 Electron 测试启动阶段超过 45 秒，未进入文件传输。第二次启动日志显示主模块加载完成约 1.4 秒，Electron 随后进入 ready；测试启动/调试连接的耗时尚未归因为产品缺陷。仅将扩展脚本的启动等待设为 120 秒并增加阶段时间记录，产品六秒直连与十五秒来源期限未放宽。原失败结果保留。

10 月 28 日同代码的实际应用启动探针约 8 秒通过。后续大文件诊断确认每个分块及进度回调重复执行全库 schema 校验，累计约 1.9 秒阻塞客户端续期；目标检查改为校验当前文献、附件版本及其待发送/覆盖/冲突记录。新增回归覆盖不遍历无关内容、同引用原地变更、畸形目标、冲突引用和重复待发送项；整个工作区的存储校验仍拒绝异常状态。

扩展脚本还修复了响应式面板替换时的旧 DOM 引用，以及完成 Fetch 清理后 CDP 偶尔无法回读响应正文的取证问题；原始失败日志保留。连续多客户端同步/传输触发合成账号现有限流后，将最后窗口验证拆为单独运行，没有调高服务限额或清空历史。传输/界面轮原始结果仍标记 failed（末项准备被 429 阻断），不改写成单次全通过；最终汇总逐项引用已通过记录。最终采用的回退记录同时包含实际 HTTP 正文摘要和独立缓存摘要。页面运行异常均为 0；限流轮的 429、窗口关闭后的预期 404 及已有开发环境提示分别保留。

本轮本地证据位于 `PaperQuay维护/20261023_移动端与账号同步/qa/m3/20261027/direct/`，包含测试原始日志、独立复核、逐步结果与截图，不随源码提交。最终文件与哈希以该目录的 `final-manifest.json` 为准。
