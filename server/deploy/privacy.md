# 账号隐私接口

此接口管理 PaperQuay 应用账号。身份服务的用户资料、密码、MFA 和恢复方式由身份服务管理；
它们不进入文库导出。部署方需提供真实的身份账号管理/删除渠道及备份保留说明，不能把应用
账号注销收据表述为身份服务和所有历史备份均已擦除。

## 导出

`GET /v1/privacy/export` 使用现有 Bearer 会话，要求设备仍有效。它输出 UTF-8 JSONL，
从一个 PostgreSQL repeatable-read 快照读取本账号全部应用表，包括删除条目的保留内容、
历史、操作回执、冲突、模型/检索回执，以及云 PDF 和解析/索引二进制。其他设备尚未同步的
内容、客户端原始文件、身份服务资料和运维备份不在本服务的读取范围内。

首行 `header` 声明账号、格式和范围。`record` 是各表非二进制字段；二进制以最多 64 KiB 的
`file-chunk` 分块输出，`file-complete` 提供完整大小和 SHA-256。末行 `complete` 提供记录数、
文件数、文件字节数，以及此前全部原始 UTF-8 行（含换行）的 SHA-256。
只有收到并验证末行和各文件收据的导出才完整。中断、取消、失效会话和超时不能生成成功回执。
请求不接受任意表名、路径或外部下载 URL。

导出按数据库游标逐行读取并逐块传输，不在服务进程内汇集整份文库或大文件。
每条 JSON 行上限 8 MiB，单次导出期限 15 分钟。流期间持续检查 JWT 到期，至少每秒重新检查
当前账号及设备状态。部署方应根据实测规模配置资源和维护窗口；这些边界不代表容量承诺。
导出包含私人材料，应由用户选择保存位置；普通应用日志不得记录其内容。

## 注销与设备清理

`GET /v1/privacy/status` 返回本账号状态和设备清理计数。
`POST /v1/privacy/close` 要求账号 ID、独立请求 UUID、精确的 `注销 ACCOUNT_UUID` 确认文字、
独立的 `deleteCloudCopies: true` 确认，以及是否请求设备清理的 `eraseDevices`。
它还要求经过签名验证、五分钟内的 OIDC `auth_time`；刷新 access token 的 `iat` 不算重新认证。
身份服务必须向该客户端的访问令牌提供真实 `auth_time`。缺失或过旧时拒绝注销，客户端应通过
系统浏览器以 `prompt=login`、`max_age=0` 重新认证；不能降级为仅检查 token 签发时间。

注销在同一事务内串行化账号写入，清除全部应用载荷和云二进制，保留最小的 issuer/subject/
账号 ID/注销请求 ID/时间拒绝重绑标记。原会话、新登录和旧游标均不能重新创建该账号。
代码不删除用户原始 PDF、不调用第三方模型或身份服务的删除接口，也不声明已经发出的第三方
请求已取消或退款。事务失败会恢复全部原数据。未知响应只能显式查询状态或重试原请求 UUID，
不能自动创建新的注销请求。

设备清理与账号注销、单份云 PDF 删除、本机缓存清理分别确认。
选择请求设备清理时，仅保留设备 UUID、会话 SHA-256 和确认时间；离线设备显示“待执行”。
设备实际清理本账号私有副本成功后，才以原验证会话调用 `POST /v1/privacy/erasure-ack`。
其他设备或新的登录会话不能代替它确认。浏览器数据被 OS 清除、设备丢失或永不联网时，服务
无法证明擦除完成，不能自动把待执行改为成功。

运行角色不能直接 DELETE 同步和付费请求历史，也不能通过设置 GUC 或修改账号列伪造注销。
两个带固定 search_path 的窄 SECURITY DEFINER 函数只处理经过账号/会话核对的注销和清理确认；
不授予角色继承、schema 所有权、触发器管理、TRUNCATE 或 RLS 绕过权限。

## 备份边界

当前数据库中的载荷在注销事务完成时被清除。已加密的历史备份按部署方公开的保留策略到期，
不能在离线备份中即时证明擦除。恢复并提升旧备份前，必须核对备份时间之后的注销记录和身份
服务删除记录，在隔离实例重新应用注销再开放写入；缺少这些记录时停止提升。
单纯恢复旧快照通过 hash 比较，不能证明隐私删除状态已追平。

此文档和自动化测试不代替部署现场的账号恢复、备份保留政策、外部身份管理和实机验收。
